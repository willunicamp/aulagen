Fundamentos e Contexto

A importância da manipulação de arquivos em apps desktop

Slide 03

Por que usar o FS no Electron?

Diferente de aplicações web tradicionais que rodam em sandboxes restringindo o acesso ao sistema de arquivos do usuário, o Electron nos concede a capacidade de interagir diretamente com o disco rígido através do módulo 'fs' (File System) do Node.js.

Persistência Local

Permite salvar configurações de usuário, caches e bancos de dados locais sem a necessidade de um servidor externo.

Interoperabilidade

Capacidade de ler arquivos de diversos formatos (.txt, .json, .csv) e integrá-los ao fluxo de dados da aplicação.

O Diferencial Desktop

A manipulação de arquivos transforma a aplicação web em uma ferramenta de produtividade real, permitindo que o usuário tenha controle total sobre onde seus dados são armazenados.

  • Criação de editores de texto/código
  • Gerenciadores de arquivos personalizados
  • Sistemas de logs offline
  • Importação e Exportação de backups
Slide 04

Recapitulação: Processo Principal vs. Processo de Renderização

Para manipular arquivos com segurança, é fundamental relembrar a arquitetura multi-processo do Electron. O acesso ao disco não acontece da mesma forma em todas as camadas da aplicação.

Main Process (Processo Principal)

O coração da aplicação. Tem acesso total às APIs do Node.js e ao sistema operacional.

  • Pode usar o módulo 'fs' livremente
  • Gerencia janelas e diálogos nativos
  • Controla a vida útil do app

Renderer Process (Renderizador)

A interface visual (Chromium). Por segurança, é isolada do sistema de arquivos.

  • Não acessa o 'fs' diretamente
  • Executa HTML, CSS e JS de UI
  • Comunica-se via IPC com o Main

Regra de Ouro da Segurança

Nunca habilite 'nodeIntegration: true' no Renderer. Sempre realize operações de leitura e escrita no Main Process para evitar que scripts maliciosos comprometam o computador do usuário.

  • Renderer solicita $ ightarrow$ IPC envia $ ightarrow$ Main executa FS $ ightarrow$ Retorna resposta
Slide 05

O Fluxo de Dados: IPC Main e Renderer

Como o módulo 'fs' opera exclusivamente no Processo Principal (Main Process), a interface do usuário (Renderer) não pode acessá-lo diretamente. Para isso, utilizamos o IPC (Inter-Process Communication) como ponte de comunicação.

Renderer → Main

O usuário clica em 'Abrir Arquivo'. O Renderer envia uma mensagem via `ipcRenderer.invoke()` solicitando a ação.

Main → Renderer

O Main Process executa a operação de FS, obtém o conteúdo do arquivo e retorna o resultado via Promise para o Renderer.

A Camada de Segurança (Preload)

Nunca exponha o módulo 'fs' ou 'ipcRenderer' diretamente no frontend. Utilize o arquivo preload.js para criar uma API segura via contextBridge.

  • Evita ataques de XSS
  • Isola privilégios do sistema operacional
  • Define exatamente quais funções o Renderer pode chamar

Integração FS + Dialogs

Tornando a aplicação interativa para o usuário final

Slide 07

Revisão: dialog.showOpenDialog

Antes de integrarmos a leitura de arquivos, precisamos relembrar como o Electron interage com o sistema operacional para permitir que o usuário selecione um arquivo de forma nativa e segura.

O que é o showOpenDialog?

É um método do módulo 'dialog' que abre uma janela de seleção de arquivos. Ele retorna uma Promise que contém as propriedades do arquivo selecionado.

  • Não acessa o conteúdo do arquivo, apenas o caminho (path)
  • Executado obrigatoriamente no Main Process
  • Permite filtrar extensões de arquivos (ex: .txt, .json)
main.js
const { dialog } = require('electron');

async function selectFile() {
  const result = await dialog.showOpenDialog({
    properties: ['openFile'],
    filters: [
      { name: 'Arquivos de Texto', extensions: ['txt', 'md'] },
      { name: 'Todos os Arquivos', extensions: ['*'] }
    ]
  });

  if (!result.canceled) {
    console.log('Arquivo selecionado:', result.filePaths[0]);
    return result.filePaths[0];
  }
  return null;
}

Propriedade properties

Define se queremos abrir um arquivo ('openFile') ou uma pasta ('openDirectory').

Propriedade filters

Restringe a visualização para que o usuário não selecione arquivos incompatíveis com a aplicação.

Slide 08

Revisão: dialog.showSaveDialog

Enquanto o showOpenDialog busca arquivos existentes, o showSaveDialog é utilizado para definir onde um novo arquivo será criado ou onde um conteúdo atual deve ser sobrescrito.

O que este método retorna?

Ele retorna uma Promise que resolve em um objeto contendo:

  • canceled: Booleano indicando se o usuário desistiu da operação.
  • filePath: O caminho completo do arquivo selecionado pelo usuário.

Configurações Comuns (Options)

filters

Permite restringir as extensões de arquivo que o usuário pode salvar.

  • Ex: [{ name: 'Text Files', extensions: ['txt'] }]

defaultPath

Sugere um nome de arquivo ou diretório inicial para facilitar a vida do usuário.

  • Ex: defaultPath: 'meu_arquivo.txt'
Slide 09

Conectando a Seleção ao Caminho do Arquivo (filePath)

A ponte entre a interface visual (Dialogs) e a manipulação de dados (FS) é o caminho do arquivo. Quando um usuário seleciona um arquivo em uma janela de diálogo, o Electron não retorna o conteúdo do arquivo, mas sim um objeto contendo o caminho absoluto no sistema operacional.

O Elo Perdido: filePath

Para que o módulo FS consiga ler ou escrever, ele precisa de uma string exata do caminho. O resultado dos Dialogs deve ser extraído cuidadosamente para evitar erros de 'undefined'.

  • showOpenDialog retorna um array de caminhos (pois permite seleção múltipla).
  • showSaveDialog retorna o caminho único selecionado pelo usuário.

Fluxo de Leitura

Dialog (Seleção) → Extração do Caminho → fs.readFile(caminho)

Fluxo de Escrita

Dialog (Destino) → Extração do Caminho → fs.writeFile(caminho, dados)

Exemplo de extração no Main Process:

main.js
// Para abertura (OpenDialog)
const { canceled, filePaths } = await dialog.showOpenDialog({});
if (!canceled) {
  const path = filePaths[0]; // Pega o primeiro arquivo selecionado
  // Agora passamos 'path' para as funções do FS
}

// Para salvamento (SaveDialog)
const { canceled, filePath } = await dialog.showSaveDialog({});
if (!canceled) {
  const path = filePath; // O caminho único escolhido
  // Agora passamos 'path' para as funções do FS
}

Implementando a Lógica do Exemplo 1 (Main Process)

Para ler um arquivo selecionado via Dialog, precisamos capturar o caminho retornado pelo `showOpenDialog` e passá-lo para o módulo `fs`. Como estamos no Main Process, temos acesso direto ao sistema de arquivos.

main.js
const { app, BrowserWindow, ipcMain, dialog } = require('electron');
const fs = require('fs').promises;

ipcMain.handle('open-and-read-file', async () => {
  // 1. Abre o diálogo de seleção de arquivo
  const { canceled, filePaths } = await dialog.showOpenDialog({
    properties: ['openFile'],
    filters: [{ name: 'Arquivos de Texto', extensions: ['txt', 'md'] }]
  });

  if (canceled || filePaths.length === 0) {
    return { success: false, message: 'Operação cancelada pelo usuário' };
  }

  try {
    // 2. Utiliza o FS para ler o conteúdo do caminho selecionado
    const filePath = filePaths[0];
    const data = await fs.readFile(filePath, 'utf8');
    
    return { success: true, content: data };
  } catch (error) {
    return { success: false, message: `Erro ao ler arquivo: ${error.message}` };
  }
});

Análise Técnica:

Observe que utilizamos a versão de Promises do módulo FS (`fs.promises`) para evitar o bloqueio da Main Thread e manter a aplicação responsiva.

  • O `filePaths[0]` extrai a string do caminho do primeiro arquivo selecionado.
  • 'utf8' é essencial para que o Node retorne uma String em vez de um Buffer binário.
  • O bloco try/catch previne crashes caso o arquivo seja deletado ou movido entre a seleção e a leitura.
Slide 13

Exemplo 2: Criar e Salvar um Novo Arquivo de Texto

Agora vamos implementar a funcionalidade inversa: permitir que o usuário escreva um conteúdo na interface (Renderer) e escolha onde salvá-lo no disco rígido através de uma caixa de diálogo nativa.

O Fluxo do Usuário

O usuário clica em 'Salvar', define o nome do arquivo e a localização, e o sistema grava os dados permanentemente.

A Engenharia por Trás

Integração entre IPC (envio do texto), Dialog (escolha do caminho) e FS (escrita física no disco).

Pontos Chave da Implementação:

Para que este exemplo funcione, precisamos de três etapas coordenadas:

  • Capturar a string do conteúdo no Frontend.
  • Disparar o `dialog.showSaveDialog` para obter o caminho (path) escolhido pelo usuário.
  • Utilizar `fs.writeFile` para persistir os dados no caminho retornado.
Slide 14

Implementando a Lógica do Exemplo 2 (Main Process)

Para salvar um arquivo, precisamos integrar o `dialog.showSaveDialog` com o método `fs.writeFile`. O fluxo consiste em capturar o caminho escolhido pelo usuário e gravar os dados recebidos via IPC.

main.js
const { ipcMain, dialog } = require('electron');
const fs = require('fs').promises;

ipcMain.handle('save-file', async (event, content) => {
  try {
    // 1. Abre a janela de diálogo para salvar
    const { filePath, canceled } = await dialog.showSaveDialog({
      title: 'Salvar Arquivo de Texto',
      defaultPath: 'meu-arquivo.txt',
      filters: [{ name: 'Arquivos de Texto', extensions: ['txt'] }]
    });

    if (canceled || !filePath) {
      return { success: false, message: 'Operação cancelada pelo usuário.' };
    }

    // 2. Grava o conteúdo no caminho selecionado
    await fs.writeFile(filePath, content, 'utf8');
    
    return { success: true, path: filePath };
  } catch (error) {
    console.error('Erro ao salvar arquivo:', error);
    return { success: false, message: 'Erro interno ao gravar arquivo.' };
  }
});

Detalhes Técnicos Importantes:

  • Utilizamos a versão de Promises do FS (`fs.promises`) para evitar o bloqueio da Main Thread com métodos síncronos.
  • O parâmetro 'utf8' garante que caracteres especiais e acentuações sejam preservados corretamente no arquivo final.
  • A validação `if (canceled)` é crucial, pois o diálogo retorna um objeto mesmo quando o usuário clica em 'Cancelar'.

Boas Práticas: Performance e UX (Non-blocking UI)

Operações de I/O (entrada e saída de arquivos) são inerentemente lentas comparadas ao processamento de CPU. Se implementadas incorretamente, elas podem 'congelar' a interface do usuário, resultando em uma experiência frustrante.

O Perigo dos Métodos Sync

Métodos como fs.readFileSync ou fs.writeFileSync bloqueiam a Event Loop do Node.js.

  • A UI para de responder (Freeze)
  • Impossibilidade de clicar em botões
  • Risco de o SO marcar a aplicação como 'Não Respondendo'

A Solução: Async/Await

Utilizar as versões baseadas em Promises do módulo fs (fs.promises) garante que a UI permaneça fluida.

  • Execução não bloqueante
  • Melhor escalabilidade da aplicação
  • Resposta imediata ao usuário enquanto o arquivo é processado

Dica de UX: Feedback Visual

Como as operações assíncronas levam tempo, nunca deixe o usuário no escuro. Implemente estados de carregamento:

  • Exiba um Spinner ou Barra de Progresso durante a leitura/escrita.
  • Desabilite o botão de 'Salvar' enquanto a operação estiver em curso para evitar duplicatas.
  • Notifique o sucesso ou erro através de diálogos ou toasts ao final da Promise.
Slide 17

Resumo da Arquitetura Implementada

Para integrar a interface do usuário com o sistema de arquivos, estabelecemos um fluxo de comunicação seguro e unidirecional. Abaixo, detalhamos como os componentes interagem para realizar as operações de leitura e escrita.

Renderer Process

A interface (UI) dispara a ação via IPC. Ela não acessa o disco diretamente por questões de segurança.

IPC Bridge

O canal de comunicação que transporta as requisições do Renderer para o Main e devolve os resultados.

Main Process

Coordena a abertura dos Dialogs, executa as funções do módulo 'fs' e gerencia o acesso ao SO.

O Ciclo de Vida da Operação:

Entenda a sequência lógica disparada em cada exemplo prático realizado nesta aula:

  • 1. Usuário clica no botão (Renderer) → Envia mensagem via ipcRenderer.
  • 2. Main Process recebe o evento → Abre o Dialog do Sistema Operacional.
  • 3. Usuário seleciona o caminho (Path) → O Dialog retorna a string do caminho ao Main.
  • 4. Módulo FS processa o arquivo no disco → Lê ou escreve os dados assincronamente.
  • 5. Resultado é enviado de volta via IPC → Interface atualiza o conteúdo para o usuário.
Desafios

Missões Práticas: Desafios de Manipulação de Arquivos

  1. Missão 1: Editor de Notas Simples - Crie uma aplicação onde o usuário possa abrir um arquivo .txt existente (via `showOpenDialog`), editar o conteúdo em um campo de texto e salvar as alterações no mesmo arquivo (utilizando `fs.writeFile`).
  2. Missão 2: Exportador de Logs - Implemente uma função que capture a data, hora e uma mensagem do usuário, salvando essas informações em um arquivo chamado `logs.txt`. O sistema deve usar o modo 'append' (`fs.appendFile`) para não apagar os logs anteriores.
  3. Missão 3: Seletor de Diretório e Listagem - Utilize o `dialog.showOpenDialog` com a opção `properties: ['openDirectory']`. Após selecionar a pasta, utilize `fs.readdir` para ler todos os arquivos do diretório e enviar a lista via IPC para ser exibida no processo de renderização.
  4. Missão 4: Validador de Extensão - Implemente um sistema de salvamento (`showSaveDialog`) que obrigue o usuário a salvar o arquivo com a extensão `.json`. Caso ele tente salvar com outra extensão, a aplicação deve exibir um alerta e solicitar a operação novamente.
