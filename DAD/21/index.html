Módulo Nativo do Node.js

CommonJS (require)

  • Sintaxe clássica e mais comum.
  • Compatível com todos os ambientes Node.
  • Código: const fs = require('fs');

ES Modules (import)

  • Sintaxe moderna do ECMAScript.
  • Requer configuração no package.json.
  • Código: import * as fs from 'fs';

Atenção:

Este módulo só está disponível no Processo Principal. Se você tentar importá-lo na janela de renderização (HTML/JS do frontend), receberá um erro de 'module not found'. Use IPC para comunicar com o renderer.

    Slide 06

    Módulo FS: Sincrono vs Assíncrono

    ❌ Síncrono (Não Recomendado)

    Funções como fs.readFileSync bloqueiam o thread principal do JavaScript. Se o arquivo for grande, a interface do usuário congela até que a leitura termine.

    • Risco de 'Not Responding' no Electron
    • Bloqueia eventos e renderização
    • Apenas para scripts de inicialização rápidos

    ✅ Assíncrono (Recomendado)

    Utiliza fs.promises ou callbacks. A UI continua responsiva enquanto o sistema operacional lê/escreve o arquivo.

    • Não bloqueia a thread principal
    • Experiência do usuário fluida
    • Padrão moderno com async/await
    exemplo_async.js
    const fs = require('fs').promises;

async function lerArquivo(caminho) {
  try {
    // Não bloqueia a UI!
    const conteudo = await fs.readFile(caminho, 'utf8');
    console.log(conteudo);
  } catch (erro) {
    console.error('Erro ao ler:', erro);
  }
}

    Módulo FS (File System)

    Após dominar janelas, IPC, menus e diálogos, o próximo passo crucial é interagir com o sistema de arquivos local. O módulo fs do Node.js permite ler, escrever, excluir e listar arquivos e diretórios.

    Operações Comuns

    O módulo 'fs' oferece métodos síncronos e assíncronos para manipulação de arquivos.

    • readFile / writeFile: Leitura e escrita básica de conteúdo.
    • accessSync: Verifica se um arquivo existe antes de operações.
    • mkdir / rmdir: Criação e remoção de diretórios.

    Abordagem Recomendada

    Em aplicações Electron modernas, prefira sempre operações assíncronas para não bloquear a UI.

    • fs.promises: API baseada em Promises (recomendado).
    • async/await: Sintaxe moderna para gerenciar fluxo de código.
    • Cuidado: Evite fs.readFileSync em threads principais ou de renderização.
    fsExample.js
    const fs = require('fs').promises;
const path = require('path');

async function processFile() {
  // Caminho absoluto para evitar erros de diretório
  const filePath = path.join(__dirname, 'data.txt');
  
  try {
    await fs.writeFile(filePath, 'Olá Electron!');
    console.log('Arquivo criado com sucesso.');
    
    const content = await fs.readFile(filePath, 'utf-8');
    console.log('Conteúdo:', content);
  } catch (err) {
    console.error('Erro ao acessar o arquivo:', err);
  }
}

      Módulo FS: Leitura de Arquivos

      Após dominar a criação de janelas, IPC (invoke/handle), menus, tray e dialogs no Electron, focaremos agora na interação com o sistema de arquivos através do módulo fs.

      Utilizaremos a função assíncrona fs.promises.readFile. Ela retorna uma Promise, permitindo que nossa interface não trave enquanto o disco lê os dados.

      main.js
      const fs = require('fs');

// Função assíncrona para ler o arquivo
async function lerArquivo(caminho) {
  try {
    // Lê o arquivo como string (utf8)
    const conteudo = await fs.promises.readFile(caminho, 'utf8');
    console.log('Conteúdo lido:', conteudo);
    return conteudo;
  } catch (erro) {
    console.error('Erro ao ler o arquivo:', erro);
    throw erro; // Repassa o erro para tratamento externo
  }
}

      Por que 'utf8'?

      Sempre especifique a codificação 'utf8' ao ler textos. Sem isso, o Node.js retornará um Buffer (objeto binário), dificultando o processamento direto do texto na interface.

        Introdução ao Módulo FS

        O módulo 'fs' (File System) permite ler, escrever e manipular arquivos diretamente no computador do usuário. É fundamental usar este módulo com cautela para manter a segurança da aplicação.

        Atenção ao Contexto

        Em Electron, o 'fs' roda no processo principal (Main Process). Não tente usar require('fs') diretamente nos arquivos de renderização (Frontend).

        Principais operações:

        Leitura de Arquivos

        Use fs.readFileSync ou fs.promises.readFile para obter o conteúdo de arquivos locais.

        Escrita de Arquivos

        Use fs.writeFileSync para salvar dados, configurações ou logs no disco do usuário.

        Gerenciamento de Pastas

        Crie diretórios com mkdir ou liste arquivos com readdir para navegar na estrutura local.

        Exemplo básico de leitura:
        const fs = require('fs');
        const conteudo = fs.readFileSync('dados.json', 'utf8');

        Slide 24

        Módulo File System (fs)

        Agora que dominamos a criação de janelas, IPC e menus, vamos manipular o sistema de arquivos do computador diretamente.

        O Problema do Bloqueio:

        Funções síncronas como `fs.readFileSync` congelam toda a interface gráfica enquanto leem o arquivo, tornando a experiência de usuário terrível.

          Não Faça (Exemplo Ruim)

          Carrega tudo em uma variável única, consumindo RAM proporcional ao tamanho do arquivo.

          • let data = fs.readFileSync('bigfile.bin');
          • console.log(data.length);

          Faça Certo (Streams)

          Use `fs.createReadStream` para ler o arquivo em pedaços (chunks), mantendo o uso de memória baixo e constante.

          • const stream = fs.createReadStream('bigfile.bin');
          • stream.on('data', chunk => { ... });

          Além disso, evite manter referências a arquivos abertos desnecessariamente. Sempre feche streams ou use promessas que garantam o fechamento adequado para liberar recursos do sistema operacional.

          Exercício 1: Clone de Arquivo

          Sabendo que já dominamos janelas, IPC, menus e dialogs, vamos focar exclusivamente no módulo fs (File System) para manipular arquivos reais.

          1. Seleção e Leitura

          Use dialog.showOpenDialog para obter o caminho (já aprendido). Agora, use fs.promises.readFile para carregar o conteúdo binário ou texto.

          2. Processamento e Escrita

          3. Lógica de Exemplo

          • Input: 'relatorio.pdf'
          • Nova Pasta: './backups/'
          • Output: './backups/relatorio_copia.pdf'

          4. Validação de Sistema

          Como estamos mexendo no sistema de arquivos real, garanta que a pasta de destino existe (use fs.mkdir com flag {recursive: true}) e trate erros de permissão.

          Agora que dominamos a interface e comunicação (IPC, Menus, Tray), vamos integrar a persistência de dados usando o módulo nativo fs do Node.js para criar um sistema de backup simples.

          1. Verificar Existência

          Use fs.existsSync() para checar se 'backup.json' está presente na pasta do projeto.

          • import fs from 'fs'; const path = './backup.json'; let dados = {}; if (!fs.existsSync(path)) { // Criar novo backup } else { // Carregar existente }

          2. Criar/Dados Padrão

          Se não existir, defina um objeto padrão e escreva-o no disco usando fs.writeFileSync().

          3. Carregar Dados

          Se o arquivo existir, leia-o e converta a string JSON para um objeto JavaScript válido.
